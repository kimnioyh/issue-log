현재 세션에서 사용자가 겪은 문제들을 Notion DB에 기록한다.
문제마다 별도의 행(페이지)으로 요약한다. 문제가 여럿이면 여러 행을 만든다.

DB 이름 기본값은 "이슈로그". 사용자가 다른 이름을 말하면 그 이름을 쓴다.

## 사전 조건

Notion MCP가 Claude Code에 연결돼 있어야 한다. 안 돼 있으면 사용자에게 연결을 안내하고 멈춘다.

## 순서

### 1. Notion 도구 로드

ToolSearch로 다음을 로드한다:
`mcp__notion__notion-search`, `mcp__notion__notion-fetch`, `mcp__notion__notion-create-pages`, `mcp__notion__notion-create-database`, `mcp__notion__notion-update-data-source`.

### 2. DB 찾기

`notion-search`로 DB 이름("이슈로그")을 검색한다. 결과에서 type이 database인 항목을 찾고, `notion-fetch`로 그 DB의 데이터소스 ID(`collection://...`)와 스키마를 얻는다.

찾았으면 4번으로. 못 찾았으면 3번.

### 3. DB가 없으면 생성

어느 Notion 페이지 아래에 만들지 사용자에게 묻는다(또는 사용자가 지정한 부모 페이지 사용). `notion-create-database`로 아래 스키마의 DB를 만든다.

**스키마 (property 이름 정확히 이대로):**
| property | type | 옵션 |
|---|---|---|
| `작업명` | title | |
| `상황` | text (rich_text) | |
| `문제` | text | |
| `이슈` | text | |
| `실행한것, 다음 계획` | text | (쉼표+공백 포함, 정확히) |
| `중요도` | select | ⭐, ⭐⭐, ⭐⭐⭐ |
| `태그` | select | 업무, 학습, 프로젝트 |
| `시간` | created_time | (자동) |

select 옵션은 반드시 생성 시점에 위 값들을 넣어둔다. Notion select는 등록 안 된 값을 자동 추가하지 않아서, 없는 값으로 페이지를 만들면 400 에러가 난다. 나중에 옵션을 더 써야 하면 `notion-update-data-source`로 먼저 추가한다.

### 4. 이 세션의 문제들을 추린다

현재 대화를 훑어 "사용자가 해결해야 했던 문제"만 뽑는다. 잡담·단순 확인은 제외하고, 판단이나 막힘이 있었던 것만.
비슷한 문제는 하나로 합치고, 성격이 다르면 나눈다. 억지로 개수를 맞추지 않는다. 진짜 문제가 하나면 한 행이다.

### 5. 문제마다 한 행 작성

각 필드를 아래 의미로 채운다. 사실만 쓰고, 세션에 없던 내용은 지어내지 않는다.

- **작업명**: 어떤 작업이었는가 (짧은 제목)
- **상황**: 당시 상황과 배경
- **문제**: 해결해야 했던 문제. goal(목표)과 gap(막힌 지점)을 같이
- **이슈**: 고민했던 기술적 이슈와 내린 판단
- **실행한것, 다음 계획**: 실제로 한 일 + 다음 계획
- **태그**: 업무 / 학습 / 프로젝트 중 하나
- **중요도**: 영향도에 따라 ⭐~⭐⭐⭐. 애매하면 ⭐⭐

`notion-create-pages`로 `data_source_id` 부모 아래에 만든다. 문제가 여럿이면 pages 배열에 한 번에.

### 6. 보고

만든 행들의 제목과 링크를 짧게 정리해 보고한다.
